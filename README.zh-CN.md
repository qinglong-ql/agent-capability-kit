# 能力三卷 · Agent Capability Kit

![能力三卷 — 索引 · 模板 · 规矩](assets/banner.svg)

> 你的 AI 装了一堆技能，但它不知道自己有什么。
> 这套文档让 AI **动手前先查目录 → 命中才读说明书 → 按手册执行**。

## 一、解决什么问题

### 打个比方

你有一个图书馆，几千本书，新来的员工（你的 AI）被要求「查一下怎么处理 PDF」。

- **瞎干**：不看图书馆，直接自己摸索 —— 做得糙，还可能错。
- **死读**：把几千本书全读一遍 —— 几小时后还是不知道用哪本。

**正确做法**：先查目录（3 分钟）→ 找到那本 PDF 的书 → **只读那一本** → 照着做。

**根本原因一句话**：AI 没有一张「我能干什么」的地图。

---

## 二、解法：两段式查找

```
第 1 步：查索引（一句话简介）
第 2 步：命中才读那一份说明书 → 按步骤执行
```

**为什么不全读？** 索引一行字，说明书几百上千字。**目录便宜，说明书贵**，所以先查目录、命中才读。

## 三、三卷分别是什么

| 卷 | 管什么 | 类比 |
|---|---|---|
| **卷一 · 索引** | 我有什么能力 | 图书馆的目录卡片 |
| **卷二 · 模板** | 以后怎么加新能力 | 新书登记表 |
| **卷三 · 规矩** | 什么时候该用哪个 | 门口贴的借阅须知 |

**三卷缺一不可**：只有索引 → 知道有什么但不知道怎么加；只有模板 → 会加但 AI 发现不了；只有规矩 → 有规矩没东西可查。**三卷齐了才闭环。**

---

## 四、为什么分「技能 / 插件 / MCP」

三者不是一回事，生效方式也不同（以你的宿主文档为准，下表是常见情况）：

| | 通俗理解 | 改完怎么生效 |
|---|---|---|
| **技能** | 一本操作手册 | 重载会话 |
| **插件** | 给 AI 自己长出一只手 | 重启宿主 |
| **MCP** | 把别人的手接过来 | 重启宿主 |

**混在一份索引里，AI 会搞错「改完要不要重启」。**

## 五、快速安装（拿到仓库后 10 分钟装好）

> 下面以 **DeepSeek Harness** 为例；其他宿主只差第 3 步的文件位置（见文末表格）。

### 第 1 步：拿到本仓库

```bash
git clone https://github.com/qinglong-ql/agent-capability-kit.git
# 或者网页上点 Code → Download ZIP，解压到任意目录
```

### 第 2 步：把模板放进技能目录

```bash
# 把 templates/ 下 3 份模板拷到你的技能目录，当「参照格式」用（别覆盖已有文件）
cp templates/*.md ~/.dsh/skills/_templates/
```

### 第 3 步：把规矩写进 system prompt 文件（最重要）

打开（没有就新建）`~/.dsh/AGENTS.md`，把 [`examples/AGENTS.md.example`](examples/AGENTS.md.example) 的内容**追加**进去，保存。

> ⚠️ 这一步做错 = 整套白装。规矩必须写进文件，不是对话里说一句。

### 第 4 步：扫描真实技能，生成索引

先打开 `tools/dump-skills.cjs`，把脚本顶部的 `dirs` 改成**你宿主的技能目录**，然后：

```bash
node tools/dump-skills.cjs        # 扫描 → %TEMP%/skills-inventory.json
node tools/gen-skills-index.cjs   # 生成 → ~/.dsh/SKILLS-INDEX.zh.md
```

插件索引同理（先改 `tools/dump-plugins.cjs` 里的 profileDir）：

```bash
node tools/dump-plugins.cjs
node tools/gen-plugins-index.cjs  # 生成 → ~/.dsh/PLUGINS-INDEX.zh.md
```

> 需要 Node.js（v18+）。四个脚本都是纯 Node，无外部依赖。

### 第 5 步：重启 + 验证

- 技能：**重载会话**
- 插件 / MCP：**重启宿主**
- 然后问它：**「你有哪些能力？」** —— 能说出分类和数量 = 装好了

### 其他宿主：第 3 步的文件位置

| 宿主 | 规矩写进哪 |
|---|---|
| **DeepSeek Harness** | `~/.dsh/AGENTS.md`（用户级） |
| **OpenClaw** | agent 的 persona / system prompt 配置 |
| **Claude Code** | 项目根 `CLAUDE.md` |
| **Cursor** | `.cursorrules` |

## 六、自己动手搭这套（可选，5 步）

> 不想用现成模板、想从零写，才需要看这节。

### 第 1 步：先看清你手上有什么

**不许凭想象写索引，必须扫真实文件。**

- 技能：找到所有 `SKILL.md`，读开头的 `name` 和 `description`
- 插件：读宿主的主配置 / manifest
- MCP：读配置里 `mcp-` 开头的条目

> 能力少（< 20 个）→ 手写；多（> 100 个）→ 用脚本（[`tools/`](tools/) 有现成的）

### 第 2 步：写卷一 · 索引

每个能力一行，**用「用户会怎么说」形容，不要用功能名**：

```markdown
| 能力名 | 用途 |
|---|---|
| `pdf` | 读取 / 创建 / 转换 / 填表 |
| `excel` | 表格读写 / 计算 / 分析 |
```

### 第 3 步：写卷二 · 模板

每份说明书包含：`name` / `description` / 适用场景（含**不适用**）/ 前置条件 / 步骤 / 输出规范 / 注意事项。

**最关键**：`description` 必须写**用户会说的原话**：

```
❌ 写「PDF 处理器」 → AI 永远匹配不上
✅ 写「当用户提到『PDF、转成PDF、读PDF』时使用」 → 能匹配
```

### 第 4 步：写卷三 · 规矩（最容易做错）

把铁规则**写进宿主的 system prompt 文件**（不能只在对话里说一句）：

```
1. 收到任务 → 先查能力索引
2. 命中 → 必须先读完整说明书再动手，禁止凭印象
3. 没命中 → 才用通用能力，并告知用户
4. 只读命中项，绝不全部通读
5. 用户点名某个能力 → 直接读，跳过索引
6. 按说明书的输出规范交付，说明验证结果
```

> 对话里说 → 这轮有效下轮忘；写进文件 → 每次会话自动加载，永远在。

### 第 5 步：验证生效

**最硬的一条：** 给它一个明显有对应技能的任务，看它会不会先查。

| 反应 | 结论 |
|---|---|
| 说「我先查一下技能索引」→ 读说明书 → 再动手 | ✅ 生效 |
| 二话不说直接干 | ❌ 没生效，检查第 4 步 |

## 七、装完长什么样

```
你的宿主根目录/
├── AGENTS.md（或 CLAUDE.md / .cursorrules）  ← 卷三：规矩
├── SKILLS-INDEX.md                            ← 卷一：技能索引
├── PLUGINS-INDEX.md                           ← 卷一：插件索引
├── MCP-INDEX.md                               ← 卷一：MCP 索引
├── SKILL-TEMPLATE.md                          ← 卷二：技能模板
├── PLUGIN-TEMPLATE.md                         ← 卷二：插件模板
└── MCP-TEMPLATE.md                            ← 卷二：MCP 模板
```

**7 个 markdown 文件，无依赖、不用编程。**

## 八、实测情况（仅供参考）

在 DeepSeek Harness（Windows）上实际建过一套：几百个技能、几十个插件、2 个 MCP，自动分类 100% 归位。**数字只代表当时那台机器，你的环境不一样。**

| 你的规模 | 建议 |
|---|---|
| < 5 个能力 | 别搞这套，直接在 system prompt 里列出 |
| 20~100 | 手写索引 + 照抄模板，约 1 小时 |
| > 100 | 必须用脚本（[`tools/`](tools/)） |

## 九、常见坑

1. **别按文件夹名归类** —— 分类看内容（name + description），不看路径
2. **规矩必须写进文件** —— 对话里说一遍没用
3. **索引每项只写一行** —— 索引是目录，不是内容
4. 描述为空不处理 → 从说明书正文捞第一句
5. 分类太少 → 「其他」堆满 → 加类，别硬塞
6. 改完不重启 → 插件 / MCP 要重启宿主
7. MCP 的 `command` 写相对路径（如 `npx`）→ 用绝对路径

## 十、适用场景

**适合**：能力 20+；经常发现「明明有工具却不用」；想要可预测、可检查、可扩展的行为。

**没必要**：能力 < 5 个；能力从不变化。
