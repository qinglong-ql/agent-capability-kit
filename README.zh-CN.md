## 一、先说人话：这东西解决什么问题

### 打个比方

你有一个图书馆，里面有几千本书。

现在来了个新人（你的 AI），你让他去「查一下怎么处理 PDF」。

**他会怎么做？**

- **情况 A（瞎干）**：他根本不看图书馆，直接自己摸索 —— 结果做得很糙，还可能做错。
- **情况 B（死读）**：他把整个图书馆的书全读一遍 —— 读了三个小时，最后还是不知道用哪本。

**正确做法是什么？**

> 先看书架上的**目录**（三分钟）→ 找到那本讲 PDF 的书 → **只读那一本** → 照着做。

**这套「能力三卷」，做的就是这件事。**

---

### 你的 AI 现在面临的问题

你给 AI 装了很多能力：技能、插件、各种工具。

但它**不知道自己有什么**。于是：

| 毛病 | 你看到的现象 | 后果 |
|---|---|---|
| **重复造轮子** | 明明有现成的 PDF 技能，它还是自己从零写 PDF 代码 | 做得差、慢、容易出错 |
| **通读症** | 为了「保险」，把几百份说明书全读一遍 | 烧掉几万 token、卡半天、还容易跑偏 |

**根本原因就一句话：它没有一张「我能干什么」的地图。**

---

## 二、解法：两段式查找

就两步，非常简单：

```
第 1 步：查目录
         ↓（发现有个「PDF 处理」技能，好像对得上）
第 2 步：只读那一份说明书
         ↓
      照着说明书做
```

**为什么不直接读全部？**
因为目录只有一行字，几百个能力也就占一点点地方；说明书才是几百上千字。

**目录便宜，说明书贵。所以先查目录，命中才读说明书。**

## 三、三卷分别是什么

| 卷 | 管什么 | 用一句话说 |
|---|---|---|
| **卷一 · 索引** | **我有什么能力** | 像图书馆的目录卡片 |
| **卷二 · 模板** | **以后怎么加新能力** | 像「新书登记表」，照格式填就行 |
| **卷三 · 规矩** | **什么时候该用哪个** | 像贴在门口的《借阅须知》 |

**三卷必须都有。**

| 只有 | 会怎样 |
|---|---|
| 只有索引 | 知道有什么，但不知道怎么加新的，也不知道什么时候该查 |
| 只有模板 | 会加了，但 AI 发现不了你加的东西 |
| 只有规矩 | 有规矩，但没东西可查 |
| **三卷齐了** | **闭环，AI 真的会先查再用** |

## 四、为什么必须分成「技能 / 插件 / MCP」三类

这是最容易搞混的地方。**这三个不是一回事**：

| | 通俗理解 | 谁提供的 | 怎么装 | 会自动出现什么工具 | **改完要做什么** |
|---|---|---|---|---|---|
| **技能** | 一本**操作手册** | 社区 / 自己写 | 放进 `skills/` 文件夹 | 不会出现新工具，AI 主动去读 | 重载会话 |
| **插件** | 给 AI **自己长出一只手** | 社区 / 自己写 | 包管理器安装 + 登记 | 插件自己定义的工具 | **重启程序** |
| **MCP** | **把别人的手接过来用** | 任何语言的独立程序 | 配置文件里加一条 | `mcp__xxx__yyy` | **重启程序** |

**记忆口诀：**
- 技能 = **怎么干**
- 插件 = **自己长出来的手**
- MCP = **把别人的手接上**

**为什么要分三份索引？**

因为它们的**生效方式不一样**：
- 技能改完 → 重载会话就行
- 插件 / MCP 改完 → **必须重启程序**

**如果混在一份索引里，AI 会搞错「改完到底要不要重启」。**

## 五、怎么给你自己的 agent 装上这套（5 步）

> 下面用通用写法。DeepSeek Harness、OpenClaw、Claude Code、Cursor 都适用 —— 具体路径见第 6 节。

### 第 1 步：先看清你手上有什么（不许瞎猜）

**这一步最重要**：不要凭想象写索引，必须扫真实文件。

**技能**：找到所有 `SKILL.md` 文件，读它们开头的 `name` 和 `description`

```
你的技能目录/**/SKILL.md
```

**插件**：读程序的主配置文件（不同宿主不一样）

**MCP**：读配置文件里 `mcp-` 开头的条目

> 数量少（比如 20 个以内）→ 手写就行
> 数量多（100 个以上）→ 用脚本扫（本项目 [`tools/`](tools/) 里有现成的）

---

### 第 2 步：写「卷一 · 索引」

给每个能力写**一行**：

```markdown
| 能力名 | 用途 |
|---|---|
| `pdf` | PDF 读取 / 创建 / 转换 / 填表 |
| `excel` | 表格读写 / 计算 / 分析 |
| `browser` | 打开网页 / 点击 / 截图 |
```

**三条纪律：**

1. **每个只写一句话**（20~120 字），**步骤留给说明书**
2. **用「用户会怎么说」形容**，不要用功能名
3. **分类要覆盖你真实用到的领域**，别硬塞

---

### 第 3 步：写「卷二 · 模板」

给每个能力建一份说明书，照着模板填：

```markdown
---
name: pdf
description: 用于处理 PDF 任务。当用户提到「PDF、转成PDF、读PDF、填表」时使用。
---

# PDF 处理

## 适用场景
- 触发词：PDF、转PDF、读PDF、PDF填表
- 不适用：用户只是问「PDF 是什么」→ 直接回答，不用本技能

## 前置条件
- 需要 Python + PyMuPDF + reportlab

## 使用步骤
1. 确认需求是读取还是创建
2. 执行
3. **验证**（渲染出来看一眼，别只看命令成功）
4. 交付（给出路径 + 打开方式）

## 输出规范
- 格式：.pdf
- 保存位置：用户指定目录，没指定就放当前目录
- 命名：中文名、按内容命名

## 注意事项
- 中文字体必须注册，否则整页方块
```

**⚠️ 最关键的一点**：`description` 那一行必须写**用户会说的原话**。

```
❌ 写「PDF 处理器」        → AI 永远匹配不上
✅ 写「当用户提到『PDF、转成PDF、读PDF』时使用」 → 能匹配上
```

---

### 第 4 步：写「卷三 · 规矩」（**最容易做错的一步**）

把下面这段，**放进你宿主的「系统提示词」文件里**：

```
【能力使用铁规则】
1. 收到任务后，先查能力索引，看有没有现成的；
2. 有匹配 → 必须先读完整说明书，按步骤做，禁止凭印象瞎做；
3. 没有匹配 → 才用通用能力，并明确告诉用户「没有对应能力，按通用方式处理」；
4. 只读命中的那一项，绝不把所有说明书读一遍；
5. 用户点名某个能力 → 直接读那个，跳过索引；
6. 做完按说明书的「输出规范」交付，并说明验证结果。
```

**⚠️ 铁律：必须写进文件，不能在对话里说一句。**

| 做法 | 效果 |
|---|---|
| 在对话框里说「以后先查技能」 | ⚠️ **这一轮有效，下一轮就忘了** |
| 写进系统提示词文件 | ✅ **每次对话开头自动全文加载，永远在** |

**你的宿主，系统提示词在哪：**

| 宿主 | 位置 |
|---|---|
| **DeepSeek Harness** | `~/.dsh/AGENTS.md`（用户级）+ 项目目录的 `AGENTS.md` |
| **OpenClaw** | agent 的 persona / system prompt 配置里 |
| **Claude Code** | 项目根目录的 `CLAUDE.md` |
| **Cursor** | 项目根目录的 `.cursorrules` |
| **自己写的 agent** | 你自己拼 system prompt 的地方 |

---

### 第 5 步：验证真的生效了

**最硬的验证方法，只有这一条：**

> 给它一个**明显有对应技能**的任务，看它会不会先查。

| 它的反应 | 结论 |
|---|---|
| 说「我先查一下技能索引」→ 然后读说明书 → 再动手 | ✅ **生效了** |
| 二话不说直接开干 | ❌ **没生效**，回去检查第 4 步 |

**其他检查项：**

| 检查什么 | 怎么查 | 通过标准 |
|---|---|---|
| 索引能查 | 问它「你有哪些能力？」 | 能说出分类和数量，不是瞎编 |
| 模板能用 | 照模板加一个新技能 | 加完它能找到并正确使用 |
| 没有通读 | 看 token 消耗 | 只读了命中那一份 |
| 索引没写错 | 抽查 3 个 | 名字、路径、描述都对得上 |

| 指标 | 我这边的情况 |

## 八、七个实测踩过的坑

→ 完整版：[`docs/07-pitfalls.md`](docs/07-pitfalls.md)

**最狠的三个：**

### ⚠️ 1. 千万别按文件夹名字归类

我图省事，按文件夹名把一整个 `expert-library/` 目录归成「人物视角」—— 结果 **200 多个风马牛不相及的能力**全挤进一个分类（因为那个文件夹里其实什么都有：亚马逊广告、法律查询、旅行订票、游戏开发）。

**分类要看内容（名字 + 描述），不能看文件夹名。**

### ⚠️ 2. 规矩必须写进文件，不能说一遍

对话里说 → 这一轮有用，下一轮就忘。
写进系统提示词文件 → 每次开头都加载，永远在。

### ⚠️ 3. 索引每项只写一行

索引写长了会拖慢、烧 token —— 而且 AI 会开始**在索引里就做判断**，反而不去翻说明书了。

**索引是目录，不是内容。**

**另外四个坑：** 描述为空没处理、分类太少导致「其他」堆满、改完忘记重启、MCP 的路径写成相对路径。

## 九、这套东西的来源

「索引 + 说明书」这个思路在 agent 圈子里很常见：一份 `INDEX` 列目录，每个能力一份 `SKILL.md` 写步骤，规矩固定写在系统提示词里。

**本项目在四个方面做了扩展：**

1. **从一卷扩到三卷**（技能 / 插件 / MCP）—— 因为它们的安装和生效方式不一样
2. **权限声明规范** —— 插件必须写清「读什么、写什么、调什么外部服务」
3. **MCP 的安全边界** —— MCP 是外部程序，权限是它自己的；「静默失败」是坏设计
4. **自动分类工具** —— 超过 100 个能力时，手工分类不现实

**没解决的问题：** 模型本身要够聪明。这套本质是「读文件 → 判断 → 执行」的多步推理，小模型容易读到一半就放弃，或者开始瞎猜。这不在系统能解决的范围里。

## 十一、适用场景

**适合用：**

- 你的 agent 有 **20 个以上**技能 / 插件 / MCP
- 你经常发现它「明明有工具却不用」
- 你希望它的行为**可预测、可检查、可扩展**
- 你想让多个 agent**共用同一套能力定义**

**没必要用：**

- 能力少于 5 个 —— 直接列在系统提示词里就行
- 能力从不变化 —— 那是一次性配置，不用搞体系
